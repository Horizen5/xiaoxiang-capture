# 数据说明

## 一、文件命名

每一页数据存成一个 JSON，文件名就是它的定位坐标：

```
c{二级分类id}_f{一级分类id}_t{三级分类id}_o{偏移量}.json
```

| 段 | 含义 |
|---|---|
| `c` | 二级分类 id（categoryId） |
| `f` | 一级分类 id（firstCategoryId） |
| `t` | 三级分类 id（thirdCategoryId），没有三级时为 0 |
| `o` | 分页偏移量，等于 `pageInfo.curPageOffset`，每页 +20 |

例：`c1003_f0_t0_o20.json` = 二级分类 1003 的第 2 页（偏移 20）。

> 早期版本只用 `c{cid}_o{off}` 命名，导致「低价捡漏」和「限时秒杀」两个三级分类
> categoryId 同为 48602、offset 都从 0 开始，文件互相覆盖。加 `t` 段就是为了修这个。

## 二、辅助文件

| 文件 | 内容 |
|---|---|
| `_category_tree.json` | 完整分类树，三级节点带 `skuCount`（该分类标称商品数） |
| `_current.json` | 小程序当前所在位置：一级/二级/三级 id 与名称、路由 |
| `_meta.jsonl` | 流水账，一行一条请求记录（时间、URL、分类、条数） |
| `_cruise.json` | 自动补页模式的运行状态 |
| `_mode.json` | 自动 / 手动开关（`{"auto": false}`） |

## 三、单个 JSON 的结构

美团风格的**模块化渲染描述**——页面不是「商品数组」，而是「组件树」，商品字段按
`elementId` 分散在 `showContents` 的不同槽位里。

```jsonc
{
  "code": 0,
  "data": {
    "cacheKey": "cate_10000955_4361010605_422616616_4",
    "pageInfo": {
      "total": 70,            // 该分类总条数（接口给的，可能小于标称 skuCount）
      "currentPage": 1,
      "pageSize": 20,
      "curPageOffset": 0,
      "nextPageOffset": 20,
      "lastPageOffset": 60
    },
    "moduleTemplateType": "tabList",
    "contents": [
      {
        "contentComponentType": "tab",
        "subModule": {
          "total": 70,
          "moduleTemplateType": "cardList",
          "contents": [ /* 每个元素是一张 skuCard */ ]
        }
      }
    ]
  }
}
```

### 商品卡里各 elementId 的含义

从真实数据反推出来的对应关系（见 `samples/c1003_f0_t0_o0.json`）：

| elementId | 类型 | 含义 |
|---|---|---|
| `6` | Image | 商品主图 URL（`p0.meituan.net` / `img.meituan.net`） |
| `8` | Image + Text | 角标图 + **商品名** |
| `9` | Text[] | 卖点标签（如「有机」「不用化学农药」） |
| `11` | PriceText | **价格**，形如 `¥6.45` |
| `12` | Tag | 促销标签 |
| `13` | AddCart | 加购按钮（无数据） |

取一个商品的写法：

```python
card = data['data']['contents'][0]['subModule']['contents'][0]
sc = card['showContents']

def pick(eid, kind='Text'):
    for e in sc.get(str(eid), []):
        info = e.get('elementInfo', {})
        if info.get('constructionType') == kind:
            return info.get('singleDataInfo', {})
    return {}

name  = pick(8)['text']
price = pick(11)['text']                       # '¥6.45'
img   = pick(6, 'Image')['image']['url']
```

## 四、图片

`live_imgs/` 下按 **CDN 原文件名**保存（如 `1b8ca70f1cc4e4ad3d38c8bc8c4b92e3245500.jpg`）。

为什么不用商品名：实测 2478 个商品里有 **312 个名字含 Windows 非法字符**
（`230g*6袋`、`/`、`:`、`?` 等），改名会失败或产生歧义；而 CDN 文件名天然唯一、可回查。

需要按名字找图时跑：

```bat
python tools\make_image_index.py            :: 只生成 image_index.csv
python tools\make_image_index.py --link     :: 额外建 live_imgs_by_name\ 硬链接
```

`image_index.csv` 的列：`sku, 商品名, 售价, 分类, 文件名, 有图, 大小`。
`--link` 用的是硬链接，不额外占空间（同一份数据两个名字）。

## 五、看板上的数字怎么算

| 显示 | 含义 |
|---|---|
| `150` | 已抓够，且等于实际条数 |
| `70-150`（黄色） | 该分类标称 150 条，目前抓到 70 条，还差 5 页 |
| `24-31`（黄色→变正常） | 标称 31 但接口只给 24 条（下架/无货），翻到底即视为抓完 |

判定规则：`已抓 >= 标称` **或** 接口翻到底（`nextPageOffset` 为空 / `end` 标记）
就算完成。否则显示差值并标黄。
